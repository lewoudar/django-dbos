Cron scheduling¶

Stack @cron on top of @task to run it on a schedule:

from django.tasks import task
from django_dbos import cron

@cron("*/5 * * * *")  # every 5 minutes
@task
def cleanup_expired_sessions(): ...

The expression uses the standard 5-field crontab syntax. A 6-field form with a leading seconds field is also accepted (DBOS supports sub-minute schedules).

Schedules are managed by DBOS, not by the Django process: the worker registers them in the system database (idempotently, on dbos_worker startup) and DBOS fires them even across restarts and deployments. Scheduled executions go through the task's queue and benefit from the same durability and retries as regular tasks.

Note

Scheduled tasks must not require arguments. django-dbos validates this when the module loads.

Run dbos_worker without --no-scheduler so it registers and fires schedules.

Timezone¶

The crontab is evaluated in Django's default timezone (TIME_ZONE) when USE_TZ is enabled, otherwise in UTC.

Sentry monitoring¶

Install the extra:

uv add django-dbos[sentry]

Scheduled tasks are then monitored with Sentry cron monitors: the monitor is upserted by Sentry on each check-in, so there is nothing to create in the UI. Its slug is derived from the task name (myapp.tasks.cleanup → myapp-tasks-cleanup).

Options of @cron:

@cron("*/5 * * * *", sentry_monitor_config=None)  # disable monitoring for this task

@cron(
    "0 0 * * *",
    sentry_monitor_config={
        "schedule": {"type": "crontab", "value": "0 0 * * *"},
        "timezone": "Europe/Paris",
        "checkin_margin": 2,  # hours of tolerance
        "max_runtime": 2 * 60 * 60,  # alert if it runs longer
    },
)

By default (no sentry_monitor_config), the monitor configuration is derived from the crontab. Sub-minute schedules cannot be represented as Sentry monitors and are simply not monitored.

Without sentry-sdk installed, everything is a no-op.
